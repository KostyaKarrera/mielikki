# Mielikki — дизайн

Дата: 2026-11-01. Статус: утверждён владельцем 2026-11-01.

Mielikki — финская богиня леса и охотничьей удачи: от неё зависит, найдёт ли охотник добычу. Инструмент отвечает на похожий вопрос: найдут ли сайт.

## 1. Зачем

Для запуска продукта главное — маркетинг, а основной канал — SEO. Нужно выйти на запуск подготовленными, чтобы потом не разбираться с проблемами продвижения и сканирования. Больше всего владелец опасается трёх вещей:

1. **Google не проиндексирует нужные страницы** (страницы услуг): закрыты, не попали в sitemap, нет canonical, остался `noindex`, на страницу нет внутренних ссылок.
2. **В индекс попадёт мусор:** служебные страницы (`kiitos`, `404`), дубли, заглушки, тестовые данные.
3. **У страниц нет целей:** непонятно, по какому запросу должна находиться каждая страница, тексты пишутся вслепую.

Mielikki — **отдельный публичный open-source CLI**, детерминированный (без вызова ИИ-моделей). Он собирает данные и проверяет сайт, а осмысление (кластеры запросов, тексты, приоритеты) происходит в сессии Claude Code, который читает машиночитаемый отчёт. Первый пользователь — сайт электромонтажной компании в Финляндии (Astro, статика, финский язык, `site`). Инструмент должен подходить для любых сайтов, в первую очередь для небольших сайтов локального бизнеса.

Почему свой, а не готовые:
- **claude-seo** (AgriciDaniel, MIT) — набор skills и агентов для Claude Code, не самостоятельный CLI. Слишком широкий (магазины, ссылки, генерация картинок), финского языка не знает.
- **squirrelscan** (MIT) — сильный детерминированный CLI с 300+ правилами, но свои правила в него не добавить, морфологии нет, подбор запросов только в платном облаке, есть телеметрия по умолчанию. Владелец решил делать **свой движок** и брать оба проекта за образец и источник правил.

## 2. Цели

- Одной командой проверить **собранный сайт (папку) до публикации** и **живой сайт по URL**, получить находки по важности с текстом «как исправить».
- Профиль **`launch`**: жёсткая проверка готовности к запуску, падает при любой блокирующей проблеме.
- **Карта целевых запросов**: каждая важная страница — свой основной запрос; проверка его использования с учётом финской морфологии, поиск каннибализации, проверка «шаблонных» страниц регионов.
- **Бесплатный сбор сырья** для подбора запросов: подсказки Google, Google Trends, разбор сайтов конкурентов.
- **После запуска:** Search Console (индексация страниц, реальные запросы), Lighthouse (производительность).
- Встраивание в CI: коды выхода, порог важности.
- Отчёт, удобный и человеку (терминал), и агенту (JSON, Markdown).
- **Полнота с первого релиза.** Владелец хочет готовый инструмент, а не MVP: всё перечисленное входит в первую версию.

## 3. Не цели

- Интернет-магазины, ссылочный профиль, генерация картинок и текстов, мониторинг изменений во времени, хостинг и облако, веб-интерфейс.
- Платные источники данных (DataForSEO, Ahrefs, SE Ranking и т.п.).
- Подбор запросов «за пользователя»: CLI собирает данные, решения принимаются в Claude Code.

## 4. Антицели (что сделает проект провалом, даже если он работает)

- **Комбайн**: сотни правил ради количества, шум из предупреждений, в котором теряются реальные блокеры.
- **Итоговая оценка 0–100.** Только находки по важности.
- **Утверждения без опоры:** правило не ссылается на документацию Google или проверенный источник и выдаёт отраслевые «статистики» за факты.
- **Ложные тревоги на финском:** проверка запроса по точному совпадению строки, которая не видит «Loviisassa» в ответ на «Loviisa».
- **Сеть без спроса:** телеметрия, обращения к сторонним сервисам, о которых пользователь не просил.
- Падение всей команды из-за одного хрупкого источника (Trends, подсказки).

## 5. Ограничения

- **Детерминированность:** одинаковый вход даёт одинаковый отчёт (порядок находок стабильный, без времени в теле находок). Никаких ИИ-вызовов.
- **Бесплатно:** только бесплатные источники и локальные инструменты.
- **Стек: TypeScript, Node.js (LTS), ESM**, пакет npm `mielikki` (имя свободно на 2026-11-01). Причина — та же экосистема, что Astro и сайт первого пользователя, запуск через `npx`, удобно в CI.
- **Публичный репозиторий, лицензия MIT.** Правила, перенесённые из claude-seo и squirrelscan (обе MIT), сопровождаются указанием авторства в `NOTICE` и ссылкой в описании правила. Зависимости только с совместимыми лицензиями (MIT, ISC, BSD, Apache-2.0).
- **Без телеметрии.** Сетевые обращения только к проверяемому сайту и к источникам, которые пользователь явно вызвал (`research`, `gsc`).
- **Приватность:** токены Search Console хранятся только локально у пользователя (каталог конфигурации в домашней папке), никогда в проекте. Отчёты не содержат секретов. Инструмент не работает с персональными данными посетителей.
- **Безопасность обхода:** содержимое сайтов — недоверенные данные. Обходчик не уходит на сторонние хосты, кроме явно разрешённых. Ограничения на размер ответа, число страниц и время.

## 6. Как пользуются

1. **Разработка сайта:** `mielikki check ./dist` после сборки, локально и в CI. Claude Code читает `--format json`, исправляет, перезапускает проверку.
2. **Перед запуском:** `mielikki check ./dist --profile launch`. Зелёный результат — условие запуска.
3. **Подбор запросов:** `mielikki research suggest`, `trends`, `competitors` → файлы данных → анализ в Claude Code → карта запросов в конфиге проекта → `check` проверяет её соблюдение.
4. **После запуска:** `mielikki check https://domain`, `mielikki perf`, `mielikki gsc …`.

## 7. Архитектура

```
вход (папка | URL) → загрузчик → модель сайта → правила → находки → отчёты
                                        ↑
                             языковой модуль (fi, …)
                             конфиг проекта (цели, исключения)
```

### 7.1 Вход

- **Папка сборки.** Файлы `*.html` превращаются в URL по правилам статического хостинга (`index.html` → `/`, `a/index.html` → `/a/`, `a.html` → `/a` и/или `/a.html`; поведение настраивается под хостинг). Базовый домен берётся из конфига (`site`), иначе определяется по canonical и sitemap, иначе абсолютные URL не проверяются. Также читаются `robots.txt`, sitemap-файлы, `404.html`. Сеть не используется.
- **URL.** Обходчик от стартовой страницы по внутренним ссылкам и sitemap. Разрешены `localhost` и частные адреса (это свой сайт; при проверке чужих сайтов предупреждение). Учитываются коды ответов, редиректы, заголовки. Ограничения: число страниц, параллельность, задержка, таймаут, максимальный размер ответа. JS не выполняется (инструмент рассчитан на SSR и SSG; отсутствие основного текста в исходном HTML — отдельная находка).

### 7.2 Модель сайта

Каждая страница разбирается один раз: URL, код ответа и заголовки (для URL), `<head>` (title, meta, canonical, robots, hreflang, OG/Twitter, viewport, lang), заголовки H1–H6, основной текст (без навигации, шапки и подвала, где это определяется), ссылки (внутренние и внешние, anchor, `rel`), картинки (src, alt, размеры, вес для локальных файлов), JSON-LD (разобранный), формы, `tel:` и `mailto:`. Плюс общие данные сайта: robots, sitemap, граф внутренних ссылок, глубина от главной.

### 7.3 Правила

- Модуль с метаданными: `id` (`категория/имя`), название, важность по умолчанию (`error` / `warning` / `info`), область (страница или сайт), применимость (папка, URL, оба), текст «как исправить», источник (ссылка на документацию Google или проект-образец).
- Правило только читает модель и конфиг, в сеть не ходит.
- Включение, выключение и смена важности — в конфиге, по маскам (`links/*`). Исключение конкретных URL — там же.
- `mielikki rules` выводит список, `mielikki rules explain <id>` — описание правила.

### 7.4 Профили

- `dev` (по умолчанию): обычная проверка. Ожидаемое для незапущенного сайта (`noindex`, `Disallow: /`) — `info`, а не ошибка, если в конфиге указано `prelaunch: true`.
- `launch`: всё блокирующее становится `error`. Добавляются проверки готовности: нет закрытия от индексации, нет маркеров заглушек (список строк в конфиге, например `MALLITEKSTI`, `lorem ipsum`, `TODO`), нет тестовых контактов (маски телефонов и почты в конфиге), у важных страниц есть цели, sitemap и robots ссылаются на боевой домен.
- Коды выхода: `0` — нет находок на пороге или выше; `1` — есть (порог `--fail-on`, по умолчанию `error`); `2` — ошибка запуска (неверный конфиг, нет входа).

### 7.5 Языковой модуль

Интерфейс: нормализация (регистр, диакритика), токенизация, основа слова, стоп-слова, пороги длины для title и description (если отличаются). В первой версии: финский (основной, с глубокими тестами), шведский, английский (см. раздел 13).

Финская специфика:
- **Основа слова**: стеммер Snowball для финского (готовая библиотека с совместимой лицензией или порт алгоритма). «Loviisa / Loviisassa / Loviisan» и «sähköasentaja / sähköasentajan» должны совпадать.
- **Сложные слова**: «sähköasennus» содержит «asennus». Совпадение части сложного слова засчитывается как частичное.
- **Топонимы** склоняются нерегулярно (Porvoo → Porvoossa). Стеммер может не справиться, поэтому в конфиге цели можно указать явные формы.

### 7.6 Конфиг проекта

Файл `mielikki.config.yaml` в корне проверяемого проекта, со схемой валидации и понятными ошибками. Примерное содержание:

```yaml
site: https://example.fi
language: fi
region: FI
prelaunch: true
input:
  dir: dist
  trailingSlash: always
business:
  type: service-area # brick-and-mortar | service-area | hybrid
  schemaType: Electrician
  name: Example Sähkö Oy
  phone: "+358 …"
  areaServed: [Loviisa, Porvoo, Helsinki, Uusimaa]
  hasReviews: false # без реальных отзывов рейтинг в schema — ошибка
exclude:
  noindexExpected: [/kiitos/, /404/]
placeholders: [MALLITEKSTI, lorem ipsum]
testContacts:
  phones: ['^\+?358 ?40 ?000']
  emails: ['@example\.']
targets:
  required: [/, /palvelut/*, /alueet/*]
  pages:
    - url: /palvelut/sahkoasennukset/
      primary: sähköasennukset loviisa
      secondary: [sähköasentaja loviisa, sähkömies porvoo]
      forms: { helsinki: [helsingissä, helsingin] }
    - url: /alueet/
      primary: sähköasentaja itä-uusimaa
rules:
  disable: [images/modern-format]
  severity: { content/word-count: info }
```

### 7.7 Отчёты

- `text` (по умолчанию в терминале): сводка по важности, затем находки по правилам, у каждой страницы и «как исправить».
- `json`: версионированная схема (`schemaVersion`), стабильный порядок. Основной формат для Claude Code.
- `md`: для issue и PR.
- Итоговой оценки нет.

## 8. Каталог правил

Источники — claude-seo (`seo-technical`, `seo-page`, `seo-local`, `seo-schema`, `seo-sitemap`, `references/quality-gates.md`, `local-schema-types.md`) и squirrelscan (`packages/rules`), плюс документация Google Search Central. Ниже — обязательный состав первой версии по категориям. Точный набор и пороги внутри категорий — решение исполнителя по этим источникам, с учётом антицели «не комбайн».

- **crawl** — robots.txt есть, корректен, не закрывает важные страницы и ресурсы; sitemap есть, валиден, указан в robots, содержит все индексируемые страницы и не содержит неиндексируемых (noindex, не-200, неканонические); `noindex` случайный или ожидаемый; глубина от главной ≤ 3; страницы-сироты; конфликты canonical с noindex и robots; основной текст отсутствует в исходном HTML.
- **core** — title (есть, уникален, длина), meta description (есть, уникальна, длина, не повторяет title, не одинаковый шаблон по всему сайту), ровно один H1, иерархия заголовков, canonical (есть, абсолютный, на себя или корректный), `lang`, charset, viewport.
- **links** — битые внутренние ссылки, ссылки на редиректы, пустые и неинформативные anchor, страницы-тупики, внешние ссылки без нужного `rel` (если требуется).
- **content** — объём текста по типу страницы (пороги — ориентир, `info`/`warning`), дубли и почти-дубли, маркеры заглушек, переспам запроса.
- **schema** — JSON-LD синтаксически корректен; тип и обязательные поля по Google Rich Results и schema.org; для бизнеса: правильный подтип (`Electrician` и т.п.), согласованность NAP со страницей и конфигом, `areaServed` для бизнеса с выездом (в том числе без адреса), нет `aggregateRating`/`Review` без реальных отзывов на странице, единая идентичность (`@id`) по сайту, без устаревших и снятых типов (HowTo; FAQ rich results).
- **local** — NAP одинаков на всех страницах и в schema; кликабельный `tel:`; город и услуга в title и H1 у страниц услуг и регионов; **swap test** для страниц регионов (если заменить название города, текст остаётся осмысленным — значит, страница шаблонная).
- **targets** — у каждой цели из конфига страница существует и индексируема; основной запрос (по основам слов) есть в title, H1, первом абзаце, description; вторичные встречаются в тексте; два URL с одним основным запросом (каннибализация); важные страницы без цели (`launch`).
- **images** — alt у значимых картинок, ширина и высота заданы, вес (порог), современные форматы (`info`), lazy loading не на первой картинке.
- **social** — OG и Twitter: title, description, image (существует, размер), url совпадает с canonical.
- **i18n** — `lang` соответствует языку конфига, hreflang корректен (если есть).
- **mobile** — viewport, запрет масштабирования.
- **legal** — есть политика конфиденциальности и ссылка на неё (для ЕС), страница контактов.
- **http** (только для URL) — коды ответов, цепочки редиректов, HTTPS и редирект с HTTP, единая форма адреса (www/без, слэш), заголовки безопасности (`info`/`warning`, без преувеличения их веса для ранжирования), сжатие, кэширование, мягкие 404.
- **a11y** — базовый набор, влияющий и на SEO, и на пользователей: alt, подписи форм, порядок заголовков, контраст по возможности статически. Полная проверка доступности — не цель.
- **ai** — `robots.txt` для ИИ-краулеров: что разрешено и что закрыто, с разделением на обучающих краулеров и поисковых (OAI-SearchBot, Claude-SearchBot и т.д.). Информационно, без навязывания решения.

## 9. Команды

| Команда                                             | Что делает                                                                                                                                                                                                                                     |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mielikki init`                                     | Создаёт `mielikki.config.yaml`: вопросы или флаги, автоопределение по сборке (язык, домен, тип schema).                                                                                                                                        |
| `mielikki check <dir\|url>` | Проверка. Флаги: `--profile`, `--format`, `--output`, `--fail-on`, `--rules`, лимиты обхода. |
| `mielikki rules [explain <id>]`                     | Список и описание правил.                                                                                                                                                                                                                      |
| `mielikki research suggest`                         | Подсказки Google по основам и регионам из конфига или флагов (`hl`, `gl`). Расширение основы буквами алфавита языка (для финского включая å, ä, ö) и шаблонами вопросов. Кэш на диске, паузы между запросами, дедупликация. Вывод JSON/CSV/MD. |
| `mielikki research trends`                          | Относительный интерес и сезонность по набору формулировок, регион FI. Источник неофициальный: при сбое понятная ошибка, остальные команды не затронуты.                                                                                        |
| `mielikki research competitors <url…>`              | Разбор чужих сайтов (с соблюдением их robots.txt, вежливый обход, ограничение страниц): структура URL, title, H1, H2, типы schema, страницы услуг и регионов, sitemap. Цель — понять, во что они целятся.                                      |
| `mielikki perf <url>`                               | Lighthouse на локальном Chrome (мобильный профиль): LCP, CLS, TBT как прокси INP, рекомендации. Опциональная зависимость: без Chrome понятная ошибка.                                                                                          |
| `mielikki gsc auth` / `gsc inspect` / `gsc queries` | OAuth (только чтение) к Search Console. Проверка индексации для URL из sitemap (URL Inspection API, с учётом квот), выгрузка запросов, показов, кликов и позиций по страницам. Сопоставление запросов с картой целей.                          |

Короткий алиас бинаря — решение исполнителя: `mk` конфликтует с существующими утилитами, нужно проверить.

## 10. Качество

- Каждое правило — модульные тесты на минимальных HTML-фикстурах (срабатывает и не срабатывает).
- Сайты-фикстуры (маленькие сборки с намеренными ошибками) и эталонные JSON-отчёты.
- Тесты финского модуля на реальных словах предметной области (sähköasentaja, sähkömies, sähköasennus, latausasema, Loviisa, Porvoo, Helsinki, Itä-Uusimaa во всех падежах, которые встречаются в текстах).
- Сетевые части (`research`, `gsc`, обходчик) — с записанными ответами, без живой сети в CI.
- CI в репозитории: линт, типы, тесты, сборка пакета.

## 11. Первое внедрение (первый сайт)

- Конфиг `mielikki.config.yaml` в `site`, шаг `check` в CI сайта с `prelaunch: true`.
- Сейчас сайт намеренно закрыт (`robots.txt` с `Disallow: /`, `noindex`), schema `Electrician` выводится только при `licensed: true`. Поэтому `launch`-проверку прогоняют на сборке с боевыми настройками. Как такую сборку получить (переменная окружения в Astro) — задача в репозитории сайта, не в Mielikki.
- Наблюдение 2026-11-01: подсказки Google по местным запросам скудные (`sähkömies porvoo` → 2 подсказки). Значит, спрос маленький и ставка — на длинные запросы «услуга + город».

## 12. Решено владельцем

- Свой движок, а не надстройка над squirrelscan.
- Детерминированный CLI, анализ в Claude Code.
- Отдельный публичный репозиторий, название Mielikki.
- Полная версия сразу, включая URL-режим, Lighthouse, Trends, конкурентов и Search Console.
- Только бесплатные источники.
- Владелец репозитория (`github.com/KostyaKarrera/mielikki`), npm-пакета и копирайта MIT — личный аккаунт KostyaKarrera. Mielikki не является активом компании первого пользователя.

## 13. Решено мной (можно пересмотреть)

- TypeScript/Node, ESM, npm-пакет `mielikki`, лицензия MIT.
- Конфиг в YAML со схемой валидации.
- Без итоговой оценки, три уровня важности.
- Профили `dev` и `launch`, флаг `prelaunch` в конфиге.
- JS не выполняется, сайты на клиентском рендеринге вне фокуса.
- Финский стеммер Snowball + явные формы в конфиге.
- **Языки первой версии: fi, sv, en.** Все три есть в Snowball, поэтому добавить их почти ничего не стоит. Глубокие предметные тесты пишем только для финского. Финляндия двуязычная, Loviisa/Lovisa и Porvoo/Borgå — двуязычные города. Для языка без модуля используется запасной вариант: нормализация без поиска основы, находки по целям с пометкой «точное совпадение».
- **Важные страницы** задаются в конфиге масками: `targets.required: ["/", "/palvelut/*", "/alueet/*"]`. В `launch` ошибка возникает, только если страница из этих масок осталась без цели. Индексируемые страницы вне масок без цели дают `info`. Если `required` не указан, проверка «нет цели» — `warning` и не блокирует.
- **«Блокирующее» — атрибут правила** `launchBlocking: true` в метаданных (переопределяется в конфиге). В `launch` повышаются до `error` только такие правила, остальные сохраняют свою важность. Блокирующими по умолчанию считаются: закрытие от индексации, отсутствие или ошибка robots и sitemap, canonical на чужой или неиндексируемый URL, битые внутренние ссылки, заглушки и тестовые контакты, невалидный JSON-LD, недостоверный рейтинг в schema, нет title или H1, важная страница без цели, каннибализация основного запроса.
- **Search Console: свой OAuth-клиент у каждого пользователя** («Desktop app» в его Google Cloud проекте, путь к JSON указывается при `gsc auth`) или Application Default Credentials (`gcloud auth application-default login`). Клиент в репозиторий не кладём, поэтому проверка приложения Google не нужна и GSC не тормозит релиз. В документации — пошаговая настройка.
- **Порядок работ:** слоями, сначала `check` и `launch` по папке, затем URL-режим, `research`, `perf`, `gsc`. Первый сайт может пользоваться `check` из git или пре-релиза до 1.0. Состав релиза 1.0 от этого не меняется: в него входит всё.
